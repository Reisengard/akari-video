## edit.json schema v0

The save file is the source of truth.

```jsonc
{
  "version": 0,
  "output": { "width": 1280, "height": 720, "fps": 30 },
  "source": {
    "path": "sample.mp4",        // relative to edit.json, or absolute
    "proxy": null                 // 720p proxy (null = use the original)
  },
  "cuts": [                       // keep ranges, in source seconds
    { "in": 5.0, "out": 10.0 },   // ascending, no overlap. Empty or missing = the whole source
    { "in": 30.0, "out": 35.0 }
  ],
  "overlays": [
    {
      "id": "cap-a",              // unique
      "html": "overlays/cap-a.html",  // relative to edit.json
      "start": 1.0,               // timeline seconds, after cuts are joined
      "duration": 4.0,
      "transform": { "x": 0, "y": -80, "scale": 1, "rotate": 0 },  // px, multiple, deg
      "vars": { "--color": "#ffffff" }  // CSS variable overrides applied to the root element
    }
  ]
}
```

- Coordinates. `transform.x` and `transform.y` are pixel coordinates in the output video resolution (`output.width` and `output.height`, for example 1280 by 720). They are not preview-display pixels. `#overlay-stage` builds the stage at the logical output resolution and attaches it to the preview with `scale()`. Preview and export share one coordinate system. The renderer `scripts/render-overlays.mjs` is the implementation source of truth for this coordinate system.
- Time. `cuts` are source seconds. `overlays.start` is timeline seconds, on the output time axis after cuts are joined.
- Overlay HTML fragment. There is exactly one root element. The fragment may contain `<style>`, and selectors stay inside the fragment. Follow the authoring rules in `CLAUDE.md`. Adjustment values are CSS variables. Animation is mostly `transform` and `opacity`. Time driving is deterministic.
- Geometry belongs to the container. Appearance belongs to the fragment. The runtime owns the container that wraps the fragment. It applies `transform` and `vars` to that container as the CSS variables `--x`, `--y`, `--scale`, and `--rotate`, and it sets `transform: translate(var(--x), var(--y)) scale(var(--scale)) rotate(var(--rotate))` on the container. It does not touch the fragment root. A geometry change still works when the fragment has its own transform. That is the guarantee in design section 5. `vars` reach `var(--color)` and the other variables inside the fragment through CSS inheritance.

### IPC command contract

Stubs are already registered in `lib.rs`.

| Command | Arguments and return | Owner |
|---|---|---|
| `video_load(path)` | Load one video (M0, already present) | Done |
| `video_play` and `video_pause` | M0, already present | Done |
| `video_toggle()` | Returns `bool` (whether playback is running) | M1 |
| `video_seek(seconds)` | Timeline seconds. Precise seek (tolerance zero) | M1 |
| `video_status()` | Returns `{ t, duration, playing }` in timeline seconds | M1 |
| `edit_load(path)` | Load edit.json, build an AVMutableComposition, return `EditSummary` | M1 |
| `export_start(edit_path, out_path)` | Start asynchronously. Progress is an event | M4 |
| `overlay_write(edit_path, overlay_id, patch)` | Read, modify, and write edit.json or HTML | M1 (`edit.rs`) |
| `autoload_path()` and `debug_flags()` | Read env used for verification (present or skeleton) | Done |

- `EditSummary` is `{ duration, cuts: usize, overlays: [{ id, html, html_path, start, duration, transform, vars }] }`. `html` is the fragment content itself. A WebView cannot fetch the file, so `edit_load` reads it on the Rust side and ships it in the summary. `html_path` is the absolute path written back to.
- `OverlayPatch` is `{ transform?, vars?, start?, duration?, html? }`. When `html` is present, replace the overlay HTML file entirely. That is the write-back for a text edit. The other fields update edit.json. This is the implementation point of design section 5: a human action always lands in the data.
- Types live in `src-tauri/src/video_plane/edit.rs`. The skeleton already defines the serde structs. That is the code shape of this contract. M4 shares them with `use crate::video_plane::edit::*`.

#### Events

Rust to JS, through `app.emit`.

| Event | Payload | Emitter |
|---|---|---|
| `export:progress` | `{ stage: string, pct: f32 }` | M4 |
| `export:done` | `{ out_path }` | M4 |
| `export:error` | `{ message }` | M4 |

Playback time is not an event. The front end polls it. `main.js` is already wired to call `video_status()` every 100 ms, and it interpolates between polls with `performance.now()`. Preview may be approximate. Tens of milliseconds either way are acceptable. Export holds the exact time.

### M1. Video plane (AVMutableComposition)

- `edit_load` parses edit.json, builds an `AVURLAsset` from the source (proxy first), inserts each cut keep-range into an `AVMutableComposition` with `insertTimeRange` (picture track and audio track), and replaces the current AVPlayer item. Cut boundaries have no gap.
- `video_seek` uses `seekToTime:toleranceBefore:toleranceAfter:` with kCMTimeZero tolerance.
- `video_status` returns `currentTime()`, the composition duration, and whether `rate() > 0`.
- Do not break M0 `video_load`, play, or pause. Single-file playback stays.
- Only M1 may add Cargo.toml dependencies. `objc2-core-media` (CMTime) and the others are already added.
- At the end of playback, treat the player as paused. `video_status.playing = false` is enough. Set `actionAtItemEnd = pause` explicitly so the screen does not go black by accident.

### M2. Overlay runtime (`ui/overlay-runtime.js`)

Exposed as `window.akari.runtime`. The skeleton already defines the API shape.

- `mount(summary)` turns `EditSummary.overlays` into DOM. Each element's `html` is already inlined, so do not fetch it. Inject one container per overlay under `#overlay-stage`. Set `data-overlay-id`, `data-start`, and `data-duration` on the container, and set `pointer-events: auto`. The stage itself stays `none`. Apply transform and vars to the root as CSS variables.
- `tick(t, playing)` updates visibility at timeline second `t`. Show the overlay when `start <= t < start + duration`. For CSS animation and Web Animations inside the fragment, set `currentTime` through `getAnimations()` to `(t - start) * 1000` so the sync is deterministic. Wall-clock time is forbidden. A seek must reproduce any time.
- Show and hide with `visibility` plus animation pause and `currentTime`. Keep the DOM so layout does not shift.
- `unmount()` removes everything.
- Rule. The runtime does not inspect injected blur or `backdrop-filter` on 4K. That is the authoring side's job. The runtime's own style changes are limited to `transform`, `opacity`, and `visibility`.

### M3. Interaction layer (`ui/interaction.js`)

Exposed as `window.akari.interaction`.

On an overlay container the runtime mounted (`[data-overlay-id]`):

- Click selects it. Selection handles use styles in `ui/interaction.css`.
- Drag moves it. Update the container's `--x` and `--y` live. On pointerup, persist with `overlay_write(edit_path, id, { transform })`.
- Double-click makes a text element `contenteditable`. Confirm on blur or Enter, then call `overlay_write(..., { html })` with the serialized fragment.
- Escape clears the selection.
- It must work with a synthetic PointerEvent. Do not check `isTrusted`. Unattended verification uses a synthetic drag.
- `selftest()` selects the first overlay, synthetic-drags it 60 px to the right, persists, and returns `{ ok, detail }`. When `debug_flags().selftest == "m3"`, `main.js` calls it 3 seconds after load and shows the result in `#status`. That wiring exists.

### M4. Export pipeline (`src-tauri/src/export/`)

`export_start(edit_path, out_path)` runs asynchronously on `std::thread` and emits events.

1. Cuts. ffmpeg slices the keep-ranges from the source original, not the proxy, and joins them. Use `filter_complex` trim plus concat, or a segment method. Re-encoding is allowed. Use H.264 High and AAC.
2. Overlay render. Use HyperFrames (`https://github.com/heygen-com/hyperframes`) as the external hand. Render the overlay HTML, a composed sheet that already has `data-start` and `data-duration`, to a transparent image sequence or a transparent movie.
   - If HyperFrames cannot be installed or does not fit, fall back to headless Chrome (`puppeteer-core` plus the system Chrome) and capture frames. If that also fails, use a static screenshot plus `overlay enable=between(t,..)`, the same static approximation as the M0 experiment. The result report must say which method was used and what it cannot do.
3. Composite. ffmpeg `overlay` stacks step 2 on step 1 and writes `out_path`.
4. Emit `export:progress` at each stage, and `export:done` at the end.
- Put intermediates in `.akari-export-tmp/` next to `out_path`, and delete that directory on success.
- The local ffmpeg 8.1.1 build has no drawtext and no libass. Text always goes through HTML.
- If the network is unavailable and an npm install cannot run, name the required packages in the result report. The integrating agent installs them.

### Verification fixtures

`scripts/make-sample.sh` (already created as a skeleton) generates these under `examples/local/`:

- `sample.mp4`. testsrc with a built-in timer, 1280x720, 30 fps, 60 seconds, plus a 440 Hz tone.
- `edit.json`. Cuts `[[5,10],[30,35]]` (10 seconds total) and overlays cap-a (start 1, duration 4, label Caption A) and cap-b (start 6, duration 4, label Caption B).
- Expected behavior. Timeline 0 to 5 seconds shows source timer 5 to 10. Timeline 5 to 10 seconds shows 30 to 35. The timer jumps at the boundary. Caption A is in the first half. Caption B is in the second half.

Verification env (`debug_flags()` and `main.js` are wired):

- `AKARI_VIDEO_AUTOLOAD=<mp4>` loads one video automatically (M0).
- `AKARI_VIDEO_AUTOLOAD_EDIT=<edit.json>` runs `edit_load` and plays.
- `AKARI_VIDEO_SELFTEST=m3` runs `interaction.selftest()` 3 seconds after load.

Keyboard (`main.js` is wired). Space toggles playback. Left and right arrow seek by 5 seconds.

### Addendum (2026-07-14). M3 scale handles

An owner request from the viewer UI round adds uniform scale on the selection handles as a formal M3 feature. The detail is in `notes-2026-07-14-viewer-ui-round.md` section 3 in the legacy repo. This addendum is only the point. That notes file was not part of this move, so it exists only in the legacy repo.

- The files are `ui/interaction.js` and `ui/interaction.css`. They stay inside the existing M3 ownership. The ownership table does not change.
- The four corner handles of the selection frame already exist in `ui/interaction.css`. Today they are display-only, with `pointer-events: none`. Make them draggable. Compute uniform scale, with the aspect ratio fixed, from the ratio of distances to the container center.
- Write-back matches an existing move drag. While the pointer is down, update the container `--scale`. On `pointerup`, commit `transform.scale` in edit.json through `overlay_write(edit_path, overlay_id, { transform })`. Do not change `--x`, `--y`, or `--rotate` during a scale drag.
- Clamp to 0.2 through 4.0. The range assumes a small overlay such as a caption or a lower third. Scaling the whole video canvas is a different use, so the range stays narrow.
- It must work with a synthetic PointerEvent. Do not check `isTrusted`. Adding a scale-drag check to the existing `selftest()` is optional. It is not a required completion condition.
